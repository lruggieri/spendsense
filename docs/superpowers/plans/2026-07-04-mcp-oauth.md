# MCP OAuth Authorization Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let interactive MCP clients (Claude Code, claude.ai) authenticate to SpendSense's MCP server via OAuth 2.1 (discovery → dynamic client registration → auth-code + PKCE) instead of a hand-copied API key, without weakening end-to-end encryption.

**Architecture:** SpendSense becomes an OAuth 2.1 Authorization Server by implementing the MCP SDK's `OAuthAuthorizationServerProvider` and passing it to `FastMCP(auth_server_provider=...)`. The SDK mounts `/authorize`, `/token`, `/register`, `/revoke` and metadata. `provider.authorize()` redirects to a Flask consent/unlock page that reuses the existing Google-login + WebAuthn-PRF unlock; on approval it mints an authorization `code` and, for encrypted accounts, carries the plaintext DEK across the back-channel gap by wrapping it under a code-derived KEK (the `oauth_code` envelope). At `/token` the DEK is recovered from the code and re-wrapped under access- and refresh-token-derived KEKs (`oauth_at`/`oauth_rt` envelopes), preserving today's "server DB alone can't decrypt" guarantee. The legacy manual API-key path is retained.

**Tech Stack:** Python 3.13, `mcp` SDK (installed at `lib/python3.13/site-packages/mcp`), Flask (web + consent page), SQLite (persistence), existing `infrastructure/crypto/encryption.py` primitives, WebAuthn PRF (existing `passkey-manager.js`).

**Design reference:** `docs/mcp-oauth-design.md` (read it first — it carries the *why*).

## Verified SDK facts (from inspecting the installed `mcp`)

- `FastMCP(auth_server_provider=..., auth=AuthSettings(...), token_verifier=..., transport_security=...)`.
- `OAuthAuthorizationServerProvider` methods: `register_client(client_info)->None`, `get_client(client_id)->OAuthClientInformationFull|None`, `authorize(client, params)->str` (returns redirect URL), `load_authorization_code(client, code:str)->AuthorizationCode|None`, `exchange_authorization_code(client, code:AuthorizationCode)->OAuthToken`, `load_refresh_token(client, token:str)->RefreshToken|None`, `exchange_refresh_token(client, token:RefreshToken, scopes)->OAuthToken`, `load_access_token(token:str)->AccessToken|None`, `revoke_token(token)->None`. All are `async`.
- Model fields (`mcp.shared.auth` / `mcp.server.auth.provider`):
  - `OAuthClientInformationFull`: `client_id, redirect_uris, client_secret, scope, grant_types, token_endpoint_auth_method, ...`
  - `OAuthToken`: `access_token, token_type, expires_in, scope, refresh_token`
  - `AuthorizationParams`: `state, scopes, code_challenge, redirect_uri, redirect_uri_provided_explicitly, resource`
  - `AuthorizationCode`: `code, scopes, expires_at, client_id, code_challenge, redirect_uri, redirect_uri_provided_explicitly, resource`
  - `RefreshToken`: `token, client_id, scopes, expires_at`
  - `AccessToken`: `token, client_id, scopes, expires_at, resource`
  - `expires_at` fields are epoch seconds (int/float). `construct_redirect_uri(base, **params)` builds the redirect.
  - Errors: `AuthorizeError`, `TokenError`, `RegistrationError` (raise these from provider methods).
- The SDK validates PKCE (`S256(verifier)==code.code_challenge`) inside its token handler before calling `exchange_authorization_code`, using the object from `load_authorization_code`. The provider never sees the raw `code_verifier`.
- Path constants: `/authorize`, `/token`, `/register`, `/revoke`. DCR gated by `AuthSettings.client_registration_options=ClientRegistrationOptions(enabled=True, valid_scopes=[...], default_scopes=[...])`.

```python
def oauth_wrap_dek_for_code(self, user_id, code, code_id, dek_b64):
    from infrastructure.crypto.encryption import hkdf_derive_kek, wrap_key
    salt = os.urandom(16)
    kek = hkdf_derive_kek(code, salt)
    wrapped = wrap_key(base64.b64decode(dek_b64), kek)
    self._encryption_repo.store_wrapped_dek(
        user_id, f"oauthcode:{code_id}", wrapped,
        base64.b64encode(salt).decode("ascii"), wrapper_type="oauth_code")

def oauth_unwrap_dek_for_code(self, user_id, code, code_id):
    from infrastructure.crypto.encryption import hkdf_derive_kek, unwrap_key
    cid = f"oauthcode:{code_id}"
    wrapped = self._encryption_repo.get_wrapped_dek(user_id, cid)
    if not wrapped:
        return None
    salt = base64.b64decode(self._encryption_repo.get_prf_salt(user_id, cid))
    return base64.b64encode(unwrap_key(wrapped, hkdf_derive_kek(code, salt))).decode("ascii")
```
`oauth_create_token_envelopes` wraps `dek` twice (credential_ids `oauthat:{grant_id}`, `oauthrt:{grant_id}`, salts `os.urandom(16)`, wrapper_types `oauth_at`/`oauth_rt`) and returns both salts b64. The `_access_token`/`_refresh_token` unwrap methods take the salt b64 in (from the grant row) rather than re-reading `get_prf_salt` — this avoids an extra DB hit on the hot path. `oauth_rewrap_for_rotation`: `delete oauthat:{grant_id}`, store new one; if `keep_prev_rt`: read current `oauthrt` envelope salt, re-store it under `oauthrt:{grant_id}:prev` (already wrapped under old RT — just copy the row), then delete+rewrap `oauthrt:{grant_id}` under new RT. Delete envelopes helper removes all three credential_ids.
